## Состояние GitHub Releases

Опубликованный [v1.0.0-rc.1](https://github.com/sonnygalyeon/whitelist-hide/releases/tag/v1.0.0-rc.1) содержит восемь установочных пакетов и `SHA256SUMS.txt`. 29 сентября каждый пакет скачан целиком; размер, SHA-256 и сигнатура формата совпали. Это проверка файлов опубликованного rc.1, а не новых исходников rc.2 или работы установленного приложения.

В последнем [workflow 36099688669](https://github.com/sonnygalyeon/whitelist-hide/actions/runs/36099688669) от 25 сентября прошли все четыре нативные сборки и три quality-job. Публикация завершилась ошибкой `v1.0.0-rc.1 belongs to another commit`: workflow пытался повторно выпустить существующую версию из другого SHA. Проверка предотвращает подмену старых пакетов; для новых изменений подготовлен rc.2.

Публикатор теперь проверяет размер, SHA-256, состояние и единственность каждого из девяти assets перед снятием статуса draft. Тесты покрывают отсутствие пакета, прерванную загрузку, повреждённые метаданные, повторный запуск и отказ перезаписывать релиз другого коммита. Они включены в CI и release quality gate.

Текст About подготовлен: «White Hide — обход DPI для Windows, macOS и Linux: встроенные движки, профили Flowseal и автоподбор для сетей РФ». На GitHub он пока не сохранён. Подключённый GitHub-инструмент не предоставляет операцию изменения About; для неё потребуется веб-интерфейс.

Отправка `feature/auto-strategy-ru` 29 сентября остановлена автоматической проверкой разрешений: запрошено отдельное подтверждение публикации исходников в публичном репозитории. Новые CI-сборки и rc.2 не запускались.

## Область проверки исходников

Проверены компиляция всех шести профилей для трёх диалектов движка, независимость TCP/QUIC/Discord правил, параметры sequence overlap/timestamp, SHA-256 исходных payload, отказ от блок-страниц и неверных HTTP-ответов, повторная проверка кандидата, очистка между попытками и прекращение перебора при ошибке очистки.

Тест `apps/desktop/tests/connection-flow.test.js` выполняет код интерфейса с DOM и имитацией нативного IPC: исходное состояние, прогресс, успешное подключение, остановка, неудачный поиск и доступность восстановления. Он не запускает реальный Tauri/helper и не заменяет проверку окна приложения на целевой ОС.

Нативные проверки Windows/macOS и `cargo check` Tauri настроены в CI, но для этой ветки пока не запускались: публикация ветки остановлена автоматической проверкой разрешений. Локальная среда не содержит полного набора нативных зависимостей Tauri. Проверка браузером также не завершилась из-за недоступного архива Chromium; DOM-тест и сборка frontend прошли.

Реальные движки с новыми аргументами в этой проверке не запускались. Их CLI/Lua-параметры сверены с закреплёнными исходниками; нативный dry-run и проверка перехвата в целевых ОС ещё нужны. Принятие параметров реальным движком будет проверяться сценариями `smoke_desktop_runtime.py`, которые теперь читают весь каталог.

Работа обхода на провайдерах РФ, воспроизведение `googlevideo`, QUIC, WebSocket и голос Discord здесь не проверялись. Автоматический тест приложения подтверждает только HTTPS/API/CDN по IPv4, что явно указано в интерфейсе.

Минимальная версия Rust поднята до 1.88 по требованиям зафиксированных зависимостей HTTPS-клиента. Для разработки рекомендуется stable Rust.
