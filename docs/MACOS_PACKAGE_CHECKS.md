- [Аудит опубликованного rc.2](https://github.com/sonnygalyeon/whitelist-hide/actions/runs/36855499499) воспроизвёл ошибку подписи старого приложения при корректной контрольной сумме DMG.

## Подтверждённая причина

У ARM64 rc.2 отсутствовал `Contents/_CodeSignature/CodeResources`; подпись компоновщика не связывала `Info.plist` и ресурсы приложения. `codesign` возвращал `code has no resources but signature indicates they must be present`. У Intel rc.2 приложение и helper не имели подписи. Универсальный `utunws` тоже не проходил полную проверку подписи всех архитектур.

В rc.3 движок выделяется в нативную архитектуру пакета и подписывается **до** вычисления манифеста SHA-256. Tauri подписывает helper, GUI executable и всё приложение с ad-hoc identity `-`. После подписи файлы внутри приложения не изменяются.

Хеши скачанных macOS DMG **точно совпали** с хешами образов, на которых CI проверил подписи и запуск GUI: ARM64 — 5 854 038 байт, Intel — 6 271 338 байт. Для Portable ZIP проверены CRC и все шесть runtime-компонентов; для DEB — версия rc.3, архитектура amd64, runtime и все шесть профилей.

## Ограничения результата

Подпись ad-hoc не удостоверяет издателя через Apple. Developer ID и notarization пока не настроены: `spctl` отклоняет пакет по политике доверия, хотя проверка целостности `codesign` проходит. Это явно сохранено в JSON-отчётах CI `macos-package-verification-arm64` и `macos-package-verification-x64`.

Запуск процесса на ARM64 runner не заменяет ручную проверку скачанного приложения на пользовательском M4 с карантином Gatekeeper. Не проверялись системный диалог разрешения, внешний вид окна и обход блокировок на конкретном провайдере РФ. [Порядок установки и диагностика](MACOS_INSTALL.md).
